# AI Event Platform v2

A local college event platform combining personalized recommendations with a grounded event-information chatbot. It includes a reproducible synthetic data pipeline, NeuMF recommendations, a hybrid RAG assistant, and a FastAPI/React scaffold.

All generated users, events, friendships, and interactions are synthetic. On Windows, install dependencies with `python -m pip install -r ml/requirements.txt -r backend/requirements.txt`, then generate data with `python -m ml.data.synthetic_generator` and `python -m ml.data.seed_db`.

Current generated data is written to `ml/data/generated/` and the SQLite database to `event_platform.db` (both ignored by Git). Model artifacts are written to `ml/artifacts/` (ignored by Git).

## Baseline evaluation

The following baseline metrics were generated by `python -m ml.evaluation.run_experiments` on the synthetic data. Evaluation ranks up to ten events that are open at each held-out positive interaction time.

| Model | Queries | Recall@10 | NDCG@10 | HitRate@10 | Catalog coverage@10 |
|---|---:|---:|---:|---:|---:|
| Popularity | 1325 | 0.8792 | 0.4622 | 0.8792 | 0.1640 |
| TF-IDF KNN | 1325 | 0.9117 | 0.5254 | 0.9117 | 0.1680 |
| Matrix Factorization | 1325 | 0.8740 | 0.4251 | 0.8740 | 0.1640 |
| NeuMF (no content) | 1325 | 0.8792 | 0.4622 | 0.8792 | 0.1640 |
| NeuMF + content | 1325 | 0.8860 | 0.4587 | 0.8860 | 0.1600 |

Warm target results are unavailable: the test split has no warm targets. Events are open for at most 30 days, but test interactions begin 38 days after the training cutoff, so open test events were posted after the cutoff. Also, 39.4% of test queries have at most ten eligible candidates, which limits how informative Recall@10 is. This run used the downloaded SBERT model (`all-MiniLM-L6-v2`). NeuMF + content did not outperform TF-IDF KNN on this synthetic split; these numbers are reported as measured. When Hugging Face is unavailable, the embedding code falls back to TF-IDF + TruncatedSVD. See [`docs/results/results.md`](docs/results/results.md) and [`docs/results/ablations.md`](docs/results/ablations.md) for all results. On Windows, rerun them with `python -m ml.evaluation.run_experiments` and `python -m ml.evaluation.ablations`.

## RAG assistant

`rag/ingest.py` builds event header, rules and FAQ chunks plus five clearly marked sample campus guides. Retrieval combines BM25, SBERT cosine similarity and reciprocal-rank fusion; relative dates and fee/category/department constraints are parsed in Python. The default generator is extractive and cites event sources as `[E123]` and campus guides as `[G:registration_process]`. Unsupported or weakly supported questions are refused. Optional Ollama and OpenAI-compatible providers can be configured with the variables in `.env.example`.

| Retriever | Hit@3 on 50 answerable questions |
|---|---:|
| BM25 | 1.000 |
| Dense SBERT | 0.840 |
| Hybrid RRF | 1.000 |

The measured refusal accuracy on 50 answerable and 10 unanswerable questions was 1.000. To build or refresh the local index and ask a question, run `python -m rag.ingest` followed by `python -m rag.cli "Where will Model Sprint EVT-001 take place?"`. Full measurements are in [`docs/results/rag_results.md`](docs/results/rag_results.md).
